# Fixed cgroup evidence transport

Pure, unintegrated transport; no OS I/O or actual execution. `encode_document(unit, label, raw)` lazily yields canonical JSONL bytes, one frame per advance. Caller drains/accepts each frame before advancing. `Decoder(unit).feed(wire)` returns a completed `{label, sha256, bytes, raw}` only after exact end/digest verification. Caller owns retained completed payloads (maximum 6 MiB); decoder releases active storage and retains only small summaries. `complete` and `finish()` describe all-six transport completeness, not evidence validity, provenance, cleanup or authorization. Any failed feed or incomplete finish permanently fences that instance.

Exact label order: `service`, `capacity-before-open`, `capacity-after-open`, `target-ancestry`, `capacity-before-work`, `capacity-after-work`. Service and target limits are 2 MiB each; four self documents are 512 KiB each. Empty/oversized documents reject. Every frame carries the same fixed `codex-cli-resource-[0-9a-f]{32}.service` unit. No arbitrary paths, document names or PIDs. Source-bound caller must separately bind service and target evidence to their actual owned identities; the envelope is not an ownership proof.

Begin/end carry exact byte count, chunk count and SHA256. Data chunks have zero-based consecutive sequence and canonical base64; raw blocks are exactly 32768 bytes except the final remainder. Strict canonical JSONL, exact keys/types, fixed order, no duplicates or retries. A maximum successful stream has 192 data frames plus 12 begin/end frames. Frames remain below the existing 45000-byte observation and 65536-byte line limits. The generator never builds a queue of all frames; queue 262144 bytes/64 entries remains the caller's independent hard limit.

`worst_case_budget()` serializes the full six-document maximum fixture to count actual evidence wire bytes. It adds the existing 3 MiB child output as 96 base64 chunks, reserving 1024 bytes framing per chunk, 40 × 45000 observation bytes, and 1 MiB additional control/terminal/cleanup framing reserve. Tests prove this declared successful combination is below the unchanged 16 MiB wire ceiling. This does not cover arbitrary excess or unknown stdout: the integration must count every emitted byte against its shared wire ceiling and reject excess. Existing child 3 MiB serialization, session 128 KiB, line/queue limits and deadlines are unchanged.

Integration and all actual metadata/stress execution remain NOT_RUN for this module. Reassembled bytes still require their original strict validators and external source/identity bindings before any action.
