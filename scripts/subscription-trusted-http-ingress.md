# Fixed authored HTTP CONNECT ingress

`create_offline_session()` creates a fresh numeric IPv4 loopback listener and bound local client, connects that client with a nonblocking bounded connect, and creates two AF_UNIX pairs. It returns `(session, client, ingress_peer, control_peer)`. The caller owns those three peers only after successful return. `session.run()` owns listener/accepted/ingress/control endpoints and its selector. `session.close()` is idempotent and supports a harness thread-start failure; it consumes the single-use session. Any unknown close result fences the next factory call. Factory exceptions close all partially acquired endpoints. Nothing adopts caller addresses, listeners, descriptors or commands.

No runtime executes on import. This is a standalone authored-client socket implementation, not current CLI proxy compatibility, a TLS implementation, authentication, external egress, or production dispatch. `production_upstream()` always refuses. There is no DNS, outbound target connector, subprocess or credential operation. Actual socket execution is a separately authorized measurement; the included tests are deterministic endpoint/selector mocks, not kernel PASS.

REQUEST/RESPONSE exactly match `subscription-trusted-egress-proxy.py`: fixed fixture.invalid:443 CONNECT/Host and the broker's 200 response. The constants are copied explicitly to avoid an implicit runtime import from a mutable sibling; one regression test compares both against the current proxy module. Both files are therefore source dependencies for measurement inventory. The original authored entry admits no additional HTTP headers, authentication headers, whitespace variants, body or early pipelining. The separate fixed WSS-shaped entry below adds exactly one prescribed header. No local 200 is fabricated: all response bytes must arrive from the owned AF_UNIX peer after all request bytes were written, and must be fully written to the client before relay admission.

The two-second handshake and five-second total session start at factory entry, including local connect and accept. A selector check after waiting and before each I/O and successful completion prevents late admission. The only accepted client is the factory-bound source tuple on the actual listener address; the listener closes after the first accept. This is fixture identity binding, not protection against a same-host privileged attacker. Socket identities and the actual current network namespace are metadata, not worker isolation proof.

Each opaque queue is at most 64KiB, headers at most4096, aggregate actual client+ingress receives at most1MiB. At the cap the next receive may observe one extra byte solely to prove overflow; that real crossing byte is counted and rejected without retention or forwarding. No padding is manufactured. Exact-cap success still requires actual EOFs. Observed bytes include handshake, delivered counts are destination writes, retained queues and partial handshake retention are reported separately. Report fields are metadata only; no raw HTTP or opaque payload is logged.

After handshake, each EOF drains its queue and half-closes the opposite write side, while opposite reads continue. Cancellation C, control EOF, malformed control, setup/selector/I/O errors, early data or deadlines all fail closed and attempt every owned close. Control readiness is processed before data readiness so pressure cannot starve cancellation. Cleanup reports individual booleans and no process/unit/descendant credit. Caller peers and measurement threads remain the harness's responsibility.

`run()` returns reason/state/elapsedMs; observedBytes and deliveredBytes each contain client/ingress; retainedBytes contains each destination queue; handshakeRetainedBytes contains request/response partial buffers. Ownership records actual address, expectedClient, listener and ingress dev/ino/type plus networkNamespace, and accepted identity after successful socket setup. Cleanup is `{closed:[bool],known,processCleanup:'NOT_ATTESTED'}`. `success` requires actual bidirectional EOF and known local cleanup. productionReady=false, modelCalls=0, credentialFilesRead=0 are fixed scope declarations, not evidence of production readiness.

Current tests exercise prefix and malicious variants, broker response/early data rejection, actual mock half-close and accounting, partial write/EAGAIN, overflow and exact-cap EOF, cancellation ordering, constructor/setup/accept/identity/close failures, post-select deadline, pre-run close and unknown-cleanup fence. No TCP/AF_UNIX runtime, CLI, auth, worker-negative connectivity, systemd or external network has been run by this implementation task. Windows does not provide the required Linux /proc/AF_UNIX fixture here; nothing is installed to change that.
