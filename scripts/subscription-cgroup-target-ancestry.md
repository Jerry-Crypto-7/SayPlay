# Actual owned target ancestry binding

This unintegrated component connects the actual EventReader target directory to a fresh common visible cgroup hierarchy. It performs no cgroup writes, unit creation/stop, PID signaling, workload, authentication or network operation. It does not read protected manager metadata. There is no CLI admission or arbitrary path/unit/PID argument.

API:

- `load_dependencies(raw, expected_hashes)` privately compiles exact captured bytes for the two fixed basenames `subscription-cgroup-common-view.py` and `subscription-candidate-resource-events.py`, after bounded size/hash checks, and returns `(sampler, events)`.
- `bind_target(reader, common_snapshot, absolute_deadline, deps)` accepts only the exact `events.EventReader` class, already opened and not failed/closed. The actual reader must originate from that module's factory. The target is derived from the reader's own UUID and the current UID's fixed ancestry; its stored path must match. The deadline is at most five seconds and clamped to the existing reader deadline.
- `validate_report(report, expected_hashes, deps)` performs pure bounded evidence replay, without file or process operations.

An existing caller with a reader from another private module must pass that same reviewed, source-bound events module as the explicit dependency. The dependency modules carry captured source hashes; Python module/object provenance remains a trusted-caller contract, not a cryptographic attestation against code running in the same interpreter. The future caller must externally bind this component's own bytes and both dependencies, and serialize access to the retained reader. No generic callback or foreign path adoption is provided.

The supplied common snapshot must be less than five seconds old and validate through the real sampler. A fresh self sample must match its observer PID/startticks, namespaces, membership, mount metadata/raw hashes, cgroup root and four fixed current-UID ancestor identities. A historical snapshot from another observer process cannot authorize a current target.

The component samples the existing reader, checks its retained directory FD's dev/inode/type and cgroup2 filesystem, and walks the root, four ancestor paths and actual UUID leaf with the sampler's bounded component-relative O_NOFOLLOW directory walker. Each opened final FD is retained through the second self sample and reader sample. Root/ancestor identities must equal the fresh common-view identities; leaf identity must equal both the retained reader FD and its samples. Subsequent view, mount, directory, optional support, file generation or monotonic event-counter changes are refused. The event reader's existing sampling quota is consumed by two samples; no budget or quota is enlarged.

Evidence retains both original EventReader samples with raw file bytes/hashes and parsed values, both fresh self snapshots, the supplied common snapshot and the six directory observations. Pure replay validates raw hashes/parsers, exact source/unit/path linkage, directory filesystem/device identity, event sequence/counter continuity and chronological bounds. This is sequential metadata evidence, not an atomic promise against a later privileged mount or cgroup mutation. It neither proves invisible ancestors nor reserves capacity.

Only newly acquired walk/view handles are closed. The caller's retained EventReader remains open, explicitly `eventReaderClosedHere=false`. All independent owned closes are attempted after failure. Unknown close or final deadline leaves the component's sticky fence set; subsequent binding is refused. The final deadline check covers report replay and serialization after close. A successful report says only `localHandlesClosed=true`; release, exhaustion, initial-host namespace and manager-namespace credit remain false. The trusted stress owner must separately recheck manager/MainPID/leaf generation, capacity, actual worker admission and full cleanup before any release decision.

The report is capped at 2 MiB. No runtime or actual cgroup experiment was performed. Scoped tests use real sampler/EventReader classes with authored kernels and preserve their parser/identity logic. They exercise full pure replay, source mismatch, foreign reader class, current-versus-historical self identity, raw/counter drift, ancestor/leaf replacement, wrong filesystem, actual mount-overlay refusal, close uncertainty with all owned closes attempted, and a post-replay deadline failure. `scratch/session8-target-ancestry-unit-v1.xml`:18 mocked PASS; v2:21 mocked PASS in0.91 seconds. Existing service, sampler, EventReader and relay sources were not modified.
