# Fixed trusted stress protocol component

Implemented offline only. This module performs no OS launch, observer query, unit creation, socket access, allocation, auth or cgroup operation. The caller must pass a private source-bound gate module and own the actual transport, persistent control channel, deadlines and cleanup. Its profiles are `candidate-resource-stress-tasks` and `candidate-resource-stress-memory`, with API phase `tasks` / `memory`.

API: `Protocol(gate, phase)`, mutable outgoing `pending` bytes, `written(actual_count)`, `receive(actual_parsed_frame)`, `authorize_observer(action)`, `cancel()`, `eof()`, `result()`. No arbitrary write body or process identifier is accepted. Constructor compares `gate.stress_start_request(phase)` to the original fixed control sandbox with only the fixed worker argv and `pipeStdin:true` changes. `stress_write_request(id,phase,action)` must exactly match processId fixed-worker, canonical base64 worker JSONL token and nonempty fixed writeId `stress-PHASE-ACTION`.

Initialize1, initialized{}, start2 and later monotonically increasing method-aware ids share one outstanding RPC. Responses before the complete actual outgoing frame write, wrong ids, wrong result schemas or error frames fail closed. The pinned `process/write` accepted response acknowledges enqueue into the exec-server writer channel, not worker read/actual pipe-write. Status starting/stdinClosed/unknownProcess fails rather than retries. The source schema requires writeId even though the old pinned README omits it. See `scratch/session8-candidate-stress-release-protocol-handoff.md` for exact pinned archive hashes and source lines.

Caller observer admission is explicitly `authorize_observer(action)`, with no fabricated digest or generic readiness payload. Its history records the trusted invocation and `observerAdmissionAttestedHere:false`; the external driver keeps actual observer receipts alongside its own canonical control writes. Calling this function is not cryptographic proof of receipt origin. A trusted child must call it only after decoding the actual permitted canonical control action from its dedicated startup/control pipe. The component cannot be exposed directly to untrusted caller RPCs.

Start permission requires the real process/start response. Ramp requires accepted start plus validated held progress; tasks release requires that same pair; memory release requires accepted ramp plus ramp-complete. Observer permission is additionally required. If a read is outstanding, permission is retained until its response and then schedules the fixed write, preserving one-outstanding ordering. Worker progress arriving via a notification before the write ACK does not release anything. Read-backed progress must also validate; ACK without progress and progress without ACK are insufficient.

Output notifications and read chunks are deduplicated by sequence and exact stream/bytes. Only verified ordered read response chunks advance the cursor and feed the incremental JSONL parser; notifications do not advance it. This permits notification/read duplication and arbitrary fragment boundaries without assuming output-only contiguous sequence numbers. All observed output must be committed before final close. Conflicting bytes, cursor skips with returned chunks, unknown records, nonempty stderr, data after terminal or incomplete output fail. The complete raw stdout remains in the result, including held and ramp records; no preceding wire bytes are stripped to manufacture a final single-object report.

Held records require the exact worker phase/count/stage fields, worker identity including fresh-proc namespace equality, unique child identities and canonical start ticks. These are worker-visible PIDs; external observer mapping and independent namespace verification remain necessary. Terminal validation binds every child identity to actual held identities, verifies exact canonical release history, elapsed<30seconds, own waits/close flags, no cleanup signals/wait errors, no false resource/model/credential claims, and phase-specific expected outcome. Tasks requires EAGAIN11; memory requires at least one own SIGKILL candidate and normal survivor release. This does not attribute an OOM by itself. Kernel resource event deltas/readback remain externally validated.

Complete requires the final accepted release, valid actual terminal JSONL, read closed/exited with exit0, complete raw bytes and no failure. Cancel is a separate finite token and never successful release. EOF before complete is failure. Cancellation or other failing terminal bytes remain archived in raw/history but do not receive completion credit. Process termination/reaping belongs to the caller and existing gate/parent cleanup; this component never fabricates it.

Bounds:128 RPC ids,32KiB outgoing control,64KiB unique decoded worker output,64 chunks per read,2MiB protocol history, at most three worker JSONL records. No local timer/wait exists here: caller must enforce the original absolute22-second work/30-second total budget around every I/O. `result()` returns a detached snapshot; received caller objects are copied before validation so later mutation cannot alter history. Limits do not authorize a runtime experiment.

Coverage includes ACK/progress ordering, observer gating, fragment/dedup/cursor failures, raw completeness, cleanup/status/identity failures, finite IDs and cancel/EOF.
