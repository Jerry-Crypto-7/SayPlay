# Retained metadata for an owned candidate unit — UNINTEGRATED

This component performs concrete read-only cgroup metadata I/O. Its factory creates a new `codex-cli-resource-UUID.service` identity; it accepts no caller unit name, path, PID, descriptor or resource limit. A future trusted outer launcher must create exactly that unit and bind its private systemd peer, MainPID generation and OOMPolicy before opening the reader. This module creates no unit and starts no workload. Its command-line entry always refuses operation without integration.

After unit creation, `reader.open()` walks the fixed current-user cgroup path with directory-relative no-follow opens, retains its own directory and file descriptors, and captures the baseline. `sample()` seeks and reads those same owned event descriptors, while separately checking the current path still resolves to the same directory/files. Every read is capped at 4096 bytes; support changes, identity changes, missing required files, counter resets, altered limits, frozen/empty leaves and read/close errors fail. The reader never substitutes zero for a missing event. Optional `memory.events.local` absence is recorded as unavailable/ENOENT and cannot silently become available later. Returned mutable records do not alias the private counter/identity state.

The exact candidate readback is memory.max 2147483648, memory.swap.max 0, pids.max 64 and memory.oom.group 0. A fresh self-cgroup observation must lie outside the newly generated leaf and its descendants. This check relies on the current cgroup namespace view; the outer integration must still establish the trusted manager/observer namespace and resource placement. Manager OOMPolicy, workload PID membership/pins, capacity admission, event-to-victim attribution and unit/namespace cleanup are NOT implemented by this reader and receive no success credit. In particular `memory.oom.group=0` alone is not proof of `OOMPolicy=continue`.

There are at most 32 samples and a caller-owned absolute deadline no more than 180 seconds away; the deadline is checked around synchronous metadata operations. This does not preempt a stuck kernel read/close, and the eventual external guardian remains required. Sampling uncertainty or any close error sets a sticky process-local fence before another reader can be created. Close attempts every other owned descriptor once and never retries a failed close against a potentially reused FD. The returned local close status is not remote unit cleanup. Read failures preserve uncertainty even when all local handles subsequently close.

All handles use CLOEXEC and never cross into the workload. No cgroup byte is written, no process is migrated, and no PID is signaled. Output consists only of fixed owned-leaf metadata, counts/hashes/raw bytes and the observed self-cgroup path; it contains no credentials or application payload. Process IDs in cgroup.procs are metadata only and are not an authorization to signal those processes. pids.current counts tasks; it is not equated to the process-list length. No strict memory.current <= memory.max claim is made.
