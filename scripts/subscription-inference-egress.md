# Fixed subscription inference egress (unintegrated)

This is executable relay code behind an import-safe factory, with deterministic syscall-mock tests. It is **not integrated into an image, capsule, dispatcher, or production default**. External DNS/TCP/TLS, subscription authentication, credentials, inference, and resource exhaustion have **NOT_RUN** status. Calling the file as a command refuses runtime integration.

## Fixed API and ownership

`create_session(absolute_deadline)` returns `(session, ingress_peer, control_peer)`. The factory creates two AF_UNIX stream pairs; only after success does the caller own the returned peers. It accepts no hostname, resolver callback, socket address, borrowed FD, environment override, or executable. On partial construction it closes every created endpoint. `session.run()` is single-use; `session.close()` is idempotent and is also required if a caller cannot start its runner. Unknown process or FD cleanup fences subsequent factories in the same module instance. This local fence must be carried into any future dispatcher; re-importing the module is not a cleanup recovery procedure.

The sole admitted request is the exact fixed byte string exported as `REQUEST`: CONNECT `chatgpt.com:443`, matching Host, and mandatory `Proxy-Connection: Keep-Alive`, including exact case/order/CRLF. Extra headers, authentication headers, early data, alternate targets, and API fallback are refused. The subscription target derives from pinned Codex commit `25af12f7e61572b0bc18ddb1008be543b91519b0`, `model-provider-info/src/lib.rs` ChatGPT-auth branch. The header shape derives from patched tungstenite commit `4fffad30fe373adbdcffab9545e9e9bf4f2fc19f`, `src/proxy.rs` lines 333–343, archived in `scratch/session8-pinned-wss-connect-shape.md`. These source facts do not prove a current authenticated CLI integration.

Only a fully validated request starts the fixed resolver. Every returned address must pass admission; the first is selected once, without retry or re-resolution. IPv4 excludes the explicit special-purpose prefixes in `SPECIAL_V4`, including globally marked special exceptions, shared space, multicast and reserved space. IPv6 permits only canonical native `2000::/3` minus `SPECIAL_V6`; mapped, translated, compatible, scoped, Teredo, 6to4, multicast and local forms are rejected. `ipaddress.is_global` is an additional check, not the whole policy. Port is exactly 443; IPv6 flow and scope are zero. Future registry changes require reviewed source updates, not caller exceptions.

The session owns its outbound socket. It sends the fixed 39-byte `RESPONSE` only after one nonblocking numeric connect, actual `SO_ERROR == 0`, and exact `getpeername()` equality to the selected sockaddr. This is a real proxy-generated CONNECT acknowledgement, not a upstream HTTP response. The session subsequently relays opaque bytes without TLS termination, token/header inspection inside the tunnel, payload logging, CA changes, or protocol translation. TLS server authentication remains the future trusted client's responsibility.

## Deadlines, accounting, and cancellation

The caller supplies one absolute monotonic deadline, at most 180 seconds from factory creation. Header admission has a two-second deadline from factory creation. DNS work is at most two seconds and must leave one second of cleanup reserve within the original absolute deadline. If insufficient reserve remains, spawning is refused. Numeric TCP connect is at most two seconds, clamped to the same absolute deadline. Checks occur around selection and I/O; final success is sealed only after cleanup within that deadline. These are additive component bounds; they do not alter existing CLI 180/200/5 policies.

The two tunnel queues are each at most 64 KiB. The **8 MiB aggregate transport-read cap** counts both real ingress and upstream bytes, including CONNECT negotiation ingress and opaque encrypted tunnel traffic. It is a separate limit from any plaintext model-output budget. The locally generated 200 response is counted in delivered bytes, not invented as upstream-observed bytes. At the cap, the loop can read one real crossing byte to distinguish excess from EOF; it counts that byte but does not forward it. Exact-cap success requires actual EOF. `observedBytes`, `deliveredBytes`, and `retainedBytes` distinguish reads, successful writes, and currently queued bytes; rejected crossing/header bytes need not remain retained. No padding or complete raw payload transcript is produced.

Control byte `C` cancels. Control EOF and malformed control are separate failures. Control events take priority over simultaneous data readiness. Partial writes, backpressure, half-closes and final EOF are explicit. Every report records phase, fixed failure label, counters, selected numeric address, resolver source/process cleanup metadata, and local cleanup outcome. Callback or numeric report fields alone are not external attestation.

## Resolver lifecycle

The fixed command is `/usr/bin/python3 -I -S /usr/bin/inference-egress-resolver.py`, with only `PATH=/usr/bin:/bin` and `LANG=C.UTF-8`, cwd `/`, DEVNULL stdin, separate bounded stdout/stderr pipes, and `close_fds=True`. The helper accepts no arguments and resolves only `chatgpt.com:443`. Its JSON is bounded to 4096 bytes and at most 16 candidates. The relay rejects nonzero exit, stderr, duplicate JSON keys, nonfinite or malformed values, and any invalid candidate.

The relay opens the fixed helper with no-follow semantics, requires a regular file on a read-only filesystem, and compares identity/hash before and after spawn. This is a source-stability observation, not executed-byte atomic attestation of Python or its dynamic libraries. Installing/binding the resolver and interpreter into an approved read-only image, inherited environment/FD admission, and positioning this trusted process outside the worker leaf are future prerequisites.

A retained `Popen` is recorded immediately after spawn, before pidfd or selector admission. Cleanup uses its pidfd where obtained. If pin admission itself fails, the sole waiter may kill its own unreaped `Popen`; it never accepts a caller PID or signals a reaped child. A failed kill still attempts bounded wait. Poll failures remain sticky unknown while termination/reaping is attempted. This fixed DNS utility uses immediate kill with a maximum one-second bounded reap reserve, not the CLI TERM grace. Process exit/reap and pin acquisition are separately reported. Any unknown wait or close result remains fenced, even if another close later returns successfully. The relay cannot guarantee process death after the absolute deadline; it reports unknown rather than granting cleanup credit.

## Validation evidence

`subscription-inference-egress.test.py` and `subscription-inference-egress-resolver.test.py` replace socket/DNS/Popen syscalls and fail on accidental unmocked network/process entry. They cover exact target/header admission, special IP ranges, every-candidate validation, one connect and peer identity, early data, control priority, partial response, real crossing-byte accounting, exact-cap EOF, factory/selector faults, post-Popen pidfd/inheritable/register failures, kill failure, wait timeout, already-exited child, poll failure and DNS output limits.

- v1: 83 PASS / 5 FAIL; Windows mock constants AF_UNIX and SIGKILL were missing. Preserved at `scratch/session8-inference-egress-unit-v1.xml`.
- v2: 88 PASS after explicit test-only Linux constant mocks.
- v3: 93 PASS, 0.52 seconds, `scratch/session8-inference-egress-unit-v3.xml`, including additional lifecycle/accounting regressions.

These tests are not Linux kernel, actual resolver, external network, subscription, auth, inference, or capsule integration evidence. The two earlier untested source drafts were captured in checkpoint 10; the implementation and test changes here are later work and do not change that historical status.

Source review follow-up: the initial core freeze `2272c27a6e181ec4aedc9af29fe356626d2d1926cdf2dcd1cccad3fbd613056e` omitted the globally reachable special-purpose AS112 prefix `2620:4f:8000::/48`. The explicit exclusion and negative regression were added from the [IANA IPv6 Special-Purpose Address Registry](https://www.iana.org/assignments/iana-ipv6-special-registry). No actual network run used the prior version.

The second source-review finding concerned failure while closing the owned resolver-source FD. `resolver_identity()` now sets the sticky unknown fence on that first close exception; task/session cleanup propagates it even before Popen, while still closing every other owned handle. Two regressions exercise the actual identity read/close path both before and after spawn. v4 had 94 PASS; final v5 has 96 PASS in 0.65 seconds (`scratch/session8-inference-egress-unit-v5.xml`). No runtime or prior checkpoint evidence was relabeled.
