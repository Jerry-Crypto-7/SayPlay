# Fixed tasks-then-memory measurement driver

The no-argument Windows entry runs tasks first and memory in a new owned unit only after the first phase passes the complete evidence evaluator. Both phases bind the same initial source-hash set. A failure or unknown cleanup fences the current driver instance; a phase flag cannot skip the tasks prerequisite. This is a credential-free diagnostic, with zero model calls and no production auth/network credit.

Each phase archives its source bytes before invoking the fixed Ubuntu24.04 relay command. The first control packet contains only the exact five observer/composition source hashes; unit ownership comes from the relay's internal observer factory. Subsequent control is limited to the fixed capsule START, heartbeat, and finite stress actions. Work starts only after both the actual capsule started frame and external observer baseline. Memory ramp requires held evidence; release requires a positive external observation and the relay's fresh write admission. Pipe-delivery events remain distinct from worker acknowledgements.

The driver retains complete bounded raw wire output, actual completed control writes, source hashes before/after, errors, and unique per-attempt artifacts. It independently replays ready identity/readback, canonical control sequence, output bytes/hash/EOF, the child protocol and direct cleanup, the namespace cleanup, exact own unit/leaf/systemd-run cleanup, and the separate raw resource-evidence validator. Historical readback objects are not normalized: a private source-bound validator compares the complete new OOMPolicycontinue/memory.oom.group0 contract.

The original inner job180s, command200s and TERM grace5s remain unchanged. The fixed outer manager guardian remains220s. The Windows client stops waiting after230s; killing that client never proves remote cleanup and invalidates the result. Local pipe/thread uncertainty also prevents success and any next phase. Each metadata/workload phase has its own stricter budgets in the reviewed child and relay; these are not extended by the driver ceiling.

Implementation is under integration and review. Sequencing tests and authored fixtures are not actual stress evidence. A real invocation is permitted only after complete source review, final integration tests, frozen-source archive verification and actual runtime prerequisites. Full acceptance remains dependent on actual fork EAGAIN/task events or aggregate allocator OOM events plus matching owned victim, complete output, and all cleanup. A shared resource readback or synthetic PASS cannot supply those outcomes.

## Failure diagnostics revision

Fixed symbolic ValueError reasons (uppercase ASCII letters, digits and underscores, at most128 characters) are retained alongside the exception type. Arbitrary exception text is not copied into this summary. The original bounded systemd_failure frame and unchanged raw output still retain the relay's actual reason and stage evidence.

A matching validated ownership frame plus a structured failure reporting notSpawned=true, unitAbsent=true, leafAbsent=true and systemdRunClosed=false is classified PRE_SPAWN_FAILURE_ABSENCE_REPORTED. This distinguishes a process never spawned from an unknown or incomplete cleanup report. Foreign ownership, boolean lookalikes, missing or uncertain absence and post-spawn failures remain CLEANUP_UNKNOWN. Every classification explicitly carries remoteCleanupCredit=false and stressValidated=false. It neither authorizes another phase nor clears the sticky failure fence; all existing full success requirements remain unchanged.

The earlier b347f5d1 failure reader stopped on the first malformed JSON line. Its archived UTF16 output ends at the first byte LF, so subsequent bytes were not captured and cannot be reconstructed from that artifact. The new reader disables parsing and dispatch after the first invalid frame but continues bounded raw draining. It records per-stream eofObserved, parseFailed and captureTruncated. Exceeding the original aggregate limit retains only the bounded prefix, explicitly marks truncation and does not claim EOF. A blocked or failed drain retains unknown status under the original process/thread cleanup limits. No extra wait, retry, network or workload was added.

Historical artifacts b347f5d1 and76ad8032 and the original32-source archive remain unchanged failures.
