# Fixed cgroup write-open worker probe — UNINTEGRATED

This additive helper tests exactly four namespace-projected paths: `/sys/fs/cgroup/cgroup.procs`, `/sys/fs/cgroup/memory.max`, and those same two paths under `/proc/1/root`. Each operation is only `open(O_WRONLY|O_CLOEXEC|O_NONBLOCK|O_NOFOLLOW)`, optional metadata `fstat`, and close of its own descriptor. It never uses O_CREAT/O_TRUNC, reads or writes a control-file byte, migrates a process, mounts a cgroup, or accepts a caller path. No cgroup layout discovery or host leaf injection is included.

An unexpected successful open remains a diagnostic FAIL even when metadata and close succeed. Its actual descriptor metadata and separate CLOSED/UNKNOWN outcome are retained. Constructor failure has NOT_CREATED cleanup. Fixed Linux errno values are interpreted independently of the replay host: 1/13 denied, 2 absent, 30 readonly. Those mechanisms are not conflated. Any other errno, boolean errno, missing operation or unknown cleanup fails strict replay. EROFS was explicitly included by the source handoff; it proves a readonly projection, not access-policy denial.

The helper compiles exact bounded bytes of read-only `/usr/bin/trusted-control-boundary-probe.py` and records their SHA-256. It reuses the unchanged base marker/private-HOME/protected-FD checks, post-lockdown status and fresh private PID/proc/mount admission. Descriptor inventories before and after the four opens must exactly equal the validated base inventory; namespace snapshots must remain equal to the base identity. A source-bound external caller must provide the expected marker and helper hash. The base marker is still `/work/trusted-control-boundary.json`; no shared gate, trampoline, supervisor, image or systemd profile is changed by this implementation.

API: `load_base() -> (private_base, sha256)`, `collect_with(base, sha256)`, `validate_report_with(base, report, expected_marker, expected_base_sha256)`. A future fixed readonly image entry may invoke the no-argument module only after the existing worker sandbox/lockdown setup. Until that reviewed integration exists, this is an unintegrated helper. The tests export `complete_report()` and `BASE_HASH` for authored offline replay; they use mocked syscalls and grant no kernel/cgroup runtime credit.

Passing these four observations would establish only failure to acquire write-capable descriptors through the tested direct/fresh-proc paths in that worker invocation. It would not establish absent aliases everywhere, aggregate exhaustion resistance, general hostile-descendant containment or a permanent capability guarantee. Earlier readonly cgroup probes, resource readbacks and historical open-write failures remain separate evidence. No actual probe, cgroup mutation, auth/credential operation, network call or source change outside these three new files was performed.
