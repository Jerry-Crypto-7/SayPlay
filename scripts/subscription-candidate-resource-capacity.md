# Fixed candidate capacity observation

`check_capacity(absolute_deadline)` reads actual Linux metadata for a current nonroot UID. Its only caller parameter is a finite absolute deadline at most five seconds away. It reads `/proc/meminfo` before and after four fixed systemd ancestors: `user.slice`, `user-UID.slice`, `user@UID.service`, and `app.slice`. Each ancestor supplies `memory.max`, `memory.current`, `pids.max`, and `pids.current`. No cgroup path, UID, thresholds or command can be supplied by the caller.

Admission requires at least 4 GiB available host memory and 4 GiB headroom at every finite ancestor memory limit: the candidate 2 GiB envelope plus 2 GiB for outside-leaf processes. Each finite ancestor task limit must have at least 128 tasks of headroom: candidate64 plus64 reserve. `max` means an explicit unlimited controller value; missing/invalid metadata fails. The cgroup root has no regular nonroot controller limit and is covered only by the host availability observation. This assumes the separately verified systemd/cgroup view and exact candidate parent placement; this module does not establish those identities.

All opens are read-only, no-follow and close-on-exec. Paths are walked through directory descriptors, reads are capped at64KiB per file, file identity is checked, and every owned descriptor gets one close attempt. Close uncertainty blocks another call in this module instance. The final deadline is checked after descriptor closure and result construction. Kernel metadata syscalls themselves are synchronous and are not made preemptible by this deadline.

The result retains18 observations with raw bytes, hashes and file identities. It is a sequential headroom observation, not an atomic snapshot, memory reservation, source of OOM attribution, or proof of resource enforcement. Concurrent workloads may change capacity after return. The trusted coordinator must call it immediately before starting the finite workload, combine it with actual manager/ancestor binding, and retain its evidence. No host policy, limit, migration, sysctl, credential or network operation is performed. This component has only mock test evidence until a separately recorded actual read occurs.
