# Fixed candidate resource worker — not integrated, no actual stress

This is a new finite workload, separate from the historical 64 MiB / 16-task experiment and the existing cgroup open-only probe. It never accesses cgroup paths, creates network sockets, reads credentials, writes migration controls or accepts caller counts, paths or PIDs. All resource enforcement claims remain false until a separately reviewed outside-leaf observer proves limits, events, identities and cleanup.

The only executable entries are `/usr/bin/candidate-resource-stress-worker.py --inside-tasks` and `--inside-memory` under a new explicitly reviewed readonly worker profile. Source entry refuses ordinary Windows/repository execution. Runtime admission checks the fixed readonly installed regular file, `/work/exec-worker` cwd, NNP1/seccomp2/zero effective and bounding capabilities, and self/PID1 proc namespace equality. These local checks are prerequisites, not proof of trusted origin or separation from an outer namespace; the future gate/trampoline and externally bound namespace/FD evidence remain required. The new profile is NOT currently integrated.

The root-confirmed future gate contract must enable `pipeStdin:true` for exactly this single fixed process and allow only the following finite canonical JSONL bytes, with no caller parameters. The existing supervisor can close trusted-parent stdin after its startup packet: a new explicit reviewed child/control seam is therefore required. This file does not silently forward anything through an old profile and does not change any gate.

| Action | Exact bytes (final `\n` is one LF) |
| --- | --- |
| start | `{"version":1,"action":"start"}\n` |
| ramp | `{"version":1,"action":"ramp"}\n` |
| release | `{"version":1,"action":"release"}\n` |
| cancel | `{"version":1,"action":"cancel"}\n` |

Tasks: await-start → working → held → released. Memory: await-start → working (two allocators to768MiB each) → held → ramping → ramp-complete → released. Caller waits for the actual held/ramp-complete notification before sending the next token. Whitespace/key changes, extra parameters, coalesced pipelining and out-of-order tokens reject. EOF is CONTROL_EOF; cancel is CANCELLED; neither is release or success. Received release frames retain their exact rawHex and state. No false ready or cgroup event frames are generated.

Tasks tries at most64 direct ordinary forks; there is no recursive child spawning. Children remain on private hold pipes. Each forked child initially blocks before work; its parent acquires a CLOEXEC pidfd, records bounded own `/proc/PID/stat` start ticks, performs pidfd liveness checks and only then writes the internal S token. Parent identity comes from its own fork return, never a caller PID. Only an EAGAIN from the actual fork operation is classified as the expected fork outcome; pipe or pidfd EAGAIN is a setup failure. A zero-child EAGAIN is not a positive workload outcome. Counts include only authored children, not all service tasks. The observer must independently prove pids.current64 and matching pids.events delta.

Memory creates exactly two own allocator children. Each retains private bytearrays in16MiB chunks:48 chunks at the hold stage (768MiB), then at most72 (1152MiB). Every4096-byte page receives nonzero data. Each individual cap is below2GiB; the combined request cap is2304MiB. Children close all inherited FDs except their own two private control/report pipes before allocation. Parent records staged H/F notifications and own wait statuses. Only a SIGKILL observed before cleanup signals is an expected allocator-victim candidate. SIGALRM/deadline, cleanup SIGKILL, arbitrary nonzero exit, MemoryError or incomplete child report cannot qualify. Actual OOM attribution still requires the external same-leaf event deltas; the worker never labels a kernel resource limit validated.

All work uses one absolute22-second deadline from entry and total30 seconds. Allocator children have an independent real-time alarm; loops and page touching check the absolute work deadline. Output is nonblocking, bounded64KiB and bounded by the total deadline; control buffering is128B. Cleanup first closes each private gate, waits up to2seconds, then uses own retained pidfds only for TERM (up to2seconds) and KILL (up to1second), always clamped to total30. No numeric PID signal is sent, even when pidfd acquisition failed. Gate EOF normally releases an unpinned waiting child to fail-exit; if own reap cannot be proven, cleanup is UNKNOWN and a sticky same-module fence blocks future dispatch. Wait, signal and close failures remain explicit. Cleanup signals invalidate a normal workload outcome. Parent waits only its own fork children; descriptor close status is retained per child.

The terminal report exposes `expectedWorkloadOutcome` rather than resource PASS: tasks needs bounded fork EAGAIN plus normal release/reap; memory needs a pre-cleanup own allocator SIGKILL plus normal release/reap of survivors. `resourceEnforcementValidated:false` is unconditional. A missing/truncated terminal or nonzero worker exit cannot be normalized into success by the future parent. Final output flushing remains within total30 and the final process return checks the clock again.
