# Owned common-view metadata service

This is a separate, unintegrated metadata-only service owner. It does not launch a stress workload, change namespace permissions, read protected manager namespace files or authenticate. The existing stress relay and historical failed attempts are unchanged.

`run(expected_source_hashes)` owns one internally generated `codex-cli-resource-<UUID>.service`. There is no caller unit, PID, command, path or callback. `FILES` contains exactly five basenames: this service, the common-view sampler, its held child, the reviewed systemd relay and the systemd probe. Fixed bounded no-follow regular-file reads check all expected hashes and generation metadata before private compilation and again after the helper finishes. These checks establish trusted-workspace source stability; they do not establish immutable mounted files or an atomic interpreter executed-byte attestation. Any future deployment must bind the reviewed source inventory and runtime placement externally.

The fixed Linux entry takes no arguments. Its first stdin JSONL is exactly `{type:'common_view_service',sourceSha256:{exact5}}`, limited to 2048 bytes and five seconds, read bytewise without overreading. It emits one bounded JSON report. `strict(raw)` rejects duplicate keys/nonfinite numbers. Pure `validate_report(report,expected_source_hashes,(sampler,))` performs no OS operations; the caller must compile the sampler from its separately verified archived bytes. `dependencies(raw)` is the fixed internal composition loader, returning sampler, child, relay and probe.

The service uses the existing private socket manager identity and a retained manager pidfd. Its fixed clean-env systemd-run command executes only `/usr/bin/python3 -I -S` and the fixed metadata child. Limits are MemoryMax 2 GiB, swap zero, TasksMax 64, RuntimeMaxSec 20, TimeoutStopSec 5 and KillMode control-group. These are helper limits, not stress/exhaustion evidence. The service's 30-second absolute budget includes bootstrap, work, cleanup and output. Work stops within 20 seconds, retaining the remainder for cleanup; no operation grants a new deadline. The external Windows wrapper has its own separate wait/cleanup ceiling and cannot infer remote cleanup from killing its client.

Before sample admission, the owner binds exact MainPID/ControlGroup, acquires its own MainPID pidfd, checks generation/non-zombie state and liveness, and reads exact resource values. The sampler's retained view is opened and sampled BEFORE writing the child's exact two-source admission. While the child remains held, the owner receives its original report, samples its retained view again, rechecks private manager/MainPID binding, generation and limits, and validates the cross-view evidence within the same five-second observation window. Only then does it send the literal release line. Full client-pipe write is not a child ACK. The helper must naturally return zero with complete stdout/stderr EOF and no stderr.

Pure replay cross-binds the actual helper raw report, source hashes, helper localHandlesClosed=true, retained observer snapshots, exact external binding, private socket component types/owner/path, distinct control/manager/helper PIDs, fixed user manager init.scope, observer PID/membership, external raw stat PID/startticks/PPID/non-zombie state, resource readback and cleanup. It does not treat manager namespace identity as observed. Sampler common-view equality remains a sequential observation of the visible cgroup hierarchy; it does not prove an initial host namespace, invisible ancestor capacity, resource reservation or exclusive OOM attribution. A later actual stress unit still requires its own leaf/ancestry binding and fresh capacity admission.

The owner keeps the helper pidfd until cleanup records actual POLLIN exit readiness (optional POLLHUP) and signal-zero ESRCH. The manager pin is closed without attempting to terminate the manager. Only the generated own unit may be stopped. An independently absent collected unit needs no stop; otherwise a nonzero stop remains an error even if later absence succeeds. Cleanup attempts all independent owned resources. Unknown close/wait/pin outcome or deadline prevents success and leaves the module's next-run fence set. Post-Popen selector/setup failure still reaches own-unit stop/reap and handle cleanup. Unit absence, leaf absence, local systemd-run reap, helper pin outcome and known local handles are separate required observations.

Child stdout is capped at 512 KiB and stderr at 64 KiB. The complete service JSON, including raw hex and repeated parsed evidence, is capped at 2 MiB. A report exceeding that aggregate cannot be emitted as success; no evidence is silently truncated to manufacture a pass. A final deadline check follows cleanup, replay and serialization. Failure after that point may prevent any final stdout, which the caller must preserve as incomplete evidence.

# Cooperative cancellation for future relay composition

The private `run(..., _cancel_event=threading.Event())` seam allows the outer
control pump to cancel metadata work. Runtime checks observe the fixed event;
cleanup disables work cancellation and still attempts every owned resource.
Any observed cancellation prevents validation and leaves the attempt fenced.
This is not a new stdin command or a production cancellation guarantee. The
standalone entry continues to use its existing fixed admission and deadlines.
No actual cancellation run has validated this later source change.
