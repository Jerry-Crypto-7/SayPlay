# Fixed HTTP ingress worker probe

Standalone new readonly helper `/usr/bin/trusted-http-worker-probe.py`, no arguments. It is not integrated into a capsule or authorized for host execution. It privately loads the fixed readonly `/usr/bin/trusted-control-boundary-probe.py` bytes, with regular/size/identity read checks. The enclosing image/helper hash inventory must bind both source files; reading and compiling bytes is not an atomic source-origin attestation. No shared historical helper is mutated.

Marker `/work/trusted-http-ingress-boundary.json` is a regular≤4096-byte readonly mount, opened through nofollow `/work` dirfd; rawHex/size/SHA/dev/ino/type and parsed object are retained. Before/after file generation metadata must agree. Exact schema extends the old ingress marker: four FIFO protectedDescriptors, two authoredProtectedObjects, trusted PID/mount namespaces, trustedIngressSocket, plus trustedHttpIngress `{address:['127.0.0.1',port],networkNamespace:'net:[positive]',listener:{dev,ino,type49152},client:{...},control:{...}}`. All socket identities are distinct. There is no accepted socket identity because accept has not occurred before this probe.

`collect_with(private_base)` performs the original open-only/fresh-proc/NNP/seccomp/capability/FD observations, then records its actual network namespace, performs one connect_ex on a fresh noninheritable/nonblocking IPv4 socket to that exact numeric port, optionally waits for writability and reads SO_ERROR, closes all owned socket/selector handles, and records its network namespace and FD inventory again. There are no retries, hostnames, scans, sends, receives, arbitrary paths or external destinations. The fixed250ms deadline includes setup and is checked after each wait/connection result; it does not extend any parent2s handshake budget.

Connection evidence contains connectEx, soError, osError, outcome, elapsedMs, socketClosed, selectorClosed and connectCalls. Preserve connected, permission-denied, unreachable, timeout and error distinctly. EINVAL is error; timeout is never denial. The completed-connect branch requires one call, finite elapsed<250ms and closed own handles. EPERM/EACCES can be permission-denied; ENETUNREACH/ECONNREFUSED/EHOSTUNREACH require a worker network namespace different from the marker's trusted namespace. Same-namespace refusal is insufficient. Unexpected successful connect always fails the boundary validator.

`validate_report_with(private_base, report, externally_bound_marker)` strictly replays the original marker/protected-path/FD evidence. Before/after network namespaces must match; before/after FD inventories must match exactly and contain only original standard descriptors. Standard descriptors and any opened private-proc descriptor cannot alias any protected socket tuple. The wrapper report is `{version:1,kind:FIXED_TRUSTED_HTTP_INGRESS_WORKER,baseReport,workerNetworkBefore,workerNetworkAfter,descriptorsAfter,connection,productionReady:false}`. baseReport.networkOperations=0 refers only to that earlier base collection; connection.connectCalls is the distinct subsequent operation. This is not an assertion of zero network syscalls for the whole report.

The parent must prove its same listener is still listening BEFORE and AFTER the worker, before its sole accept, and prove the trusted client can subsequently complete the authorized exchange. The worker cannot attest listener liveness from its inaccessible namespace. This standalone report alone therefore supplies no capsule/network-isolation credit. Existing lockdown does not itself deny socket/connect; no such claim is made. Actual app-server invocation, CLI HTTP traffic, TLS, authentication, external egress and resource exhaustion remain untested here.

Tests are deterministic mocks and strict authored report replay, not kernel observations. They cover immediate/asynchronous connection results, delayed readiness, precise errno distinctions, invalid/extra/missing marker/report fields, changed FD/net identity, readonly file guards, partial cleanup failure and external marker binding. No actual sockets or capsule launch occur in this implementation task.

Offline replay uses explicit Linux x86_64 pending-connect wire values115/11/114, not the validator host errno table. Initial861cfb8d source mistakenly used host constants; archived in scratch/session8-http-worker-before-linux-errno and superseded after P2 review. Dedicated positive Linux115→111 and invalid/bool/host112 cases exercise the cross-platform boundary. No historical runtime is relabeled.

## Explicit denial before socket creation

New connection fields stage, socketCreated and socketCleanup distinguish constructor admission from later setup/connect. A separate socket-permission-denied branch is valid only for stage=socket-create, socketCreated=false, socketCleanup=NOT_CREATED, socketClosed=false, selectorClosed=true, connectCalls=0, connectEx/soError=null and exact integer osError EPERM1 or EACCES13. Base marker/FD checks and a different worker network namespace remain required, plus the parent's independent live listener observations. It asserts denial of IPv4 socket creation, never a performed connect to the port.

A successfully allocated socket starts UNKNOWN cleanup until its actual close records CLOSED. Failures during setblocking/set_inheritable, socket ENOMEM/EINVAL, timeout, successful connection or unknown cleanup remain rejected. The original complete-connect branch requires stage=complete/created=true/CLOSED. No filter or network policy changed.

Historical actual388c3a08 reported osError1 and zero connect calls without an operation stage; it remains FAIL and cannot be retroactively called constructor denial.
