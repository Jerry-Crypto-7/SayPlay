## Každý pokus, včetně neúspěchů

Run používá `version: reality-compiler-review-run-v2`, digest experimentu, `NOT_RUN | IN_PROGRESS | FINISHED` a pole `attempts` podle `attemptSchema`. Prázdný běh je NOT_RUN. Každý plánovaný case × repetition má rameno before i after. FINISHED znamená úplné pokrytí, **nikoli úspěch**. Pořadí ramen předem zapsat do journalu a střídat pro omezení vlivu zahřátí; před experimentem neměnit timeout podle výsledků.

Pokus se zapíše do append-only externího journalu **před odesláním**. Po pádu se původní pokus doplní jako interrupted se zachovaným call journalem, nikoli smaže. Export obsahuje všechna ID a sekvenční `attempt`, retry ukazuje přes `retryOf` na předchozí pokus stejného slotu. Validátor odmítne mezeru v řetězci, duplicitní ID, neplánovaný případ a neúplné FINISHED; nemůže odhalit kompletně zatajený nebo přečíslovaný journal bez porovnání s původními soubory. Počet všech pokusů a failures se reportuje vedle výsledků prvních pokusů, nikdy jen nejrychlejší úspěšný retry.

Zaznamenat live/prepared/cache, outcome, error, původní proposal a hash parametrů, oddělené supplement soubory, raw journal, wall elapsed, stage durations a nullable bytes/usage. `modelCalls` zahrnuje všechny skutečně zahájené provider calls. Cena `usd` zůstává null. Timeout, cancel a browser close nejsou důkazem ukončení vzdálené inference: `remoteCompletion: unknown`, dokud není skutečný důkaz dokončení. Žádný call znamená `not-started`.

Délky preflight/provider/parse/validation/acceptance/lowering/mesh/frame/interaction/compare jsou oddělené. Nezměřené nebo nedokončené fáze mají null. Provider není klientské fetch čekání a fáze mohou být vnořené či překryté: nesčítat je automaticky. Frame znamená render completion, ne scanout. Interakce znamená přijatý vstup a vykonané pravidlo v runtime; není to záruka sémantické správnosti. Zdrojový i ordinary prompt journal mají samostatné výsledky; live/prepared/cache se neagregují dohromady.

## Skutečné potvrzení a nezávislé review

Nový interaktivní runner musí po návrhu zastavit a nechat člověka skutečně přečíst sedm oblastí v UI. Potvrzení lze zaznamenat teprve po skutečném vstupu. `actor: human` není instrukce pro skript, ale popis doložené události. Automaticky vyplněný test má pouze fixture status a nesmí se vydávat za lidský pokus. Tento offline kontrakt není náhrada takového runneru.

Session bridge toto oddělení implementuje: pouze předvyplní zmrazený zdroj a otevře panel. V `manual-live` nikdy nekliká na source-submit/source-confirm ani nevybírá sedm kontrol. Člověk osobně odešle zdroj, zkontroluje parametry, potvrdí, provede zmrazený input log a timer intervenci v produktu. Recorder vyžaduje pozorovaný submit, zobrazený review panel, sedm jednotlivých native `change` událostí a následný native confirm. Samotný přijatý projekt bez těchto událostí nezíská human completion. `isTrusted` rozlišuje syntetické DOM dispatch od nativních událostí, **není důkazem lidské identity** (například browser automation může také vytvořit trusted klik). Integrace nesmí automatizovat ruční kroky; identita/nezávislost hodnotitele musí být ověřena zvlášť.

Review obsahuje pseudonym hodnotitele, proposalHash, všech sedm unikátních klíčů pro confirmed, decision, časy shownAtMs/decidedAtMs relativně k začátku pokusu a odkaz na záznam. `humanWaitMs` je přesně jejich rozdíl; bez pozorované události je null. Změna zdroje, supplementu nebo návrhu vyžaduje nové potvrzení nového hashe. Missing/conflict se nejprve eviduje jako clarification-required; případné doplnění je nový zaznamenaný pokus, nikoli smazaná chyba. Zamítnutí má outcome review-rejected a skutečný záznam.

Source completed bez lidského confirmed kontrakt odmítne. Ordinary prompty tento source review krok nemají. Potvrzení parametrů nemění `semanticReview: NOT_RUN`. Nezávislé sémantické review patří do odděleného souboru s hodnotitelem, hashem hodnoceného návrhu, pravidly/citacemi, rozhodnutími a zdůvodněním. Validátor vrací `humanIdentityVerified: false`: formát a hash samy neověřují člověka ani význam.

## Report a otevřené brány

Použít `validateReviewRun(manifest, run)` a následně ověřit hashe referencí obou souborů. V reportu zachovat úplné počty podle outcome, pokrytí, původ scén a rozdíl mezi prvními pokusy/retry. Pro každý vstupní druh a původ uvést N, median/p95 po fázích a wall time, human wait samostatně, failures s důvody. Malá development sada není statistický důkaz splnění velké série. Bez sémantického review zůstává otázka zhoršení významu otevřená, i když je latence lepší.

Původní cíle se nemění: source median 30 s / p95 60 s, ordinary prompt p95 15 s, edit p95 8 s. Překročení je FAIL; NOT_RUN není nula. A9 vyžaduje navíc skutečně nezávisle zmrazených 10 zdrojů × 3 (5 complete / 3 missing / 2 conflict), 10 ordinary promptů, ≥27/30 dokončených párů, všechny kritické invarianty a 15/15 správných zastavení. Tento development kontrakt záměrně neumí certifikovat nezávislost. A10 vyžaduje skutečné nezávislé sémantické hodnocení a pět lidí; zatím NOT_RUN.

## Praktické použití nového session bridge

`runInteractiveReviewSession` přijímá již otevřený Playwright Browser, lokální produkční baseURL, manifest/slot, `readArtifact`, nový `createReviewArtifactSink` a explicitní transport. Nevytváří server, proces CLI ani inference přístup. Artifact reader musí být omezený na adresář experimentu včetně symlinků; SHA-256 kontrola není filesystem permission ani sandbox. Ověřené input/task bytes jsou zkopírované do paměti a pozdější změna souboru je během session nenahradí.

Konkrétní filesystem integrace je `createReviewArtifactReader` v `scripts/reality-compiler-artifact-reader.ts`; používá ji fixture smoke. Vyžaduje explicitní absolutní kanonický kořen, relativní cesty s lomítky, běžné soubory a výchozí limit 16 MiB na soubor. Odmítá traversal, Windows device/ADS aliasy a všechny symlinky či junctions, včetně těch mířících dovnitř kořene. Kontroluje identitu souboru před/po čtení a vrací vlastní kopii bajtů. Není atomickým OS sandboxem: strom a jeho předci musí být chráněni před souběžným nepřátelským přepisováním; hardlinky ani swap-and-restore závod tím nejsou vyloučené. Hash kontrolu nad vrácenými bajty nadále provádí protokol.

V `manual-live` musí caller dodat `reviewerId`, `readiness()` a `emit(request, signal)`. Readiness se kontroluje před otevřením browser contextu i znovu těsně před každým provider call. Musí uvést skutečně ověřený současný WSL dispatcher/runtime/sandbox a přesnou frozen config. Callback s booleanem ani jeho hash tuto validaci **neprovádí**; caller musí připojit výsledek existujícího validovaného launcheru. Model v provider requestu musí odpovídat manifestu. Chybějící readiness/reviewer, neplánovaný slot nebo změněné bytes/konfigurace skončí před inferencí. API fallback není podporovaný.

Aktuální bridge je úmyslně **source-only, jeden request na pokus, bez supplementu**. `input` je přesný UTF-8 zdroj; `inputLog` je JSON pole skutečných TraceInput `{tick, actor, actionId, target?}`; `intervention` je JSON `{ruleId,durationTicks,forkTick,observationTick}`. Dokončení vyžaduje shodu logu a všech čtyř intervenčních hodnot s přijatým compare a doložený frame. Operátor má použít pause/step ovládání pro předepsané ticky; libovolné odlišné vstupy se neprohlásí za srovnatelný běh. Clarification se archivuje a ukončí pokus. Následné doplnění vyžaduje další explicitní protokolovou integraci; runner je neslučuje se zdrojem ani neskrývá do retry. Ordinary prompt série a automatický scheduler obou ramen zůstávají otevřené.

Runner zapisuje journal před odesláním. Uloží HTTP source request včetně raw JSON, response/status/Server-Timing, přesný návrh a proposal hash, provider request/response a jejich bajty, předanou usage, native UI události, klientský pipeline journal a source/compare snapshot. Nejde o zachycení raw CLI token streamu; ten musí archivovat skutečný transport. HTTP a provider bajty jsou v artefaktech rozlišené. Nezměřené fáze zůstávají null. Lidský interval je rozdíl monotónních browser timestampů mezi zobrazením panelu a rozhodnutím, nikoli rozdíl jejich přijetí pollingem. Absolutní čas konce je zarovnán na recorder receipt a začátek odvozen odečtením browser intervalu: oba absolutní endpointy jsou přibližné, délka se pollingem nezkrátí na falešnou nulu. Raw browser/receipt timestampy a způsob zarovnání jsou zachované; obrácený/neplatný browser clock se odmítne. Časový interval není důkazem lidské identity.

Bez potvrzení, při timeoutu/cancel/browser close i při neúspěšném zavření contextu vzniká terminal artefakt; dřívější failure důvod se nepřepisuje chybou cleanup. Sealed journal se nemění. Pozdější pozorovaná odpověď provideru jde do `late-provider.jsonl`; nelze z ní zpětně přepsat timeout na success. Neověřené vzdálené dokončení zůstává unknown. `previousRun` umožňuje validovat úplný retry řetězec; nové pokusy se nesmí ukládat přes předchozí.

## Samostatné měření připraveného ordinary promptu

`scripts/reality-compiler-prompt-recorder.ts` a `scripts/reality-compiler-prompt-browser.ts` měří existující ordinary UI přes skutečný lokální POST sessions a následné GET/SSE. Jde výhradně o připravené scény. Server musí mít upstream/refine vypnuté; browser navíc povolí jediný přesný `{prompt}` a čtení vzniklé session, blokuje `live:true`, ostatní API i cizí origin. Raw POST, bajty, response a HTTP/SSE metadata se archivují s průběžnými pipeline snapshoty, device/build odkazy a terminal stavem. Raw tělo SSE ani background server fáze tím nejsou zachycené; neznámé fáze zůstávají null.

Výstup má vlastní `prepared-prompt-browser-v1`, `protocolAttempt:null`, `modelCalls:0`, žádné lidské pozorování a `liveMeasurement:NOT_RUN`. Odděluje endpoint `display` od `interaction`: nestačí ready flag, vyžaduje skutečný draw s trojúhelníky, dokončený first-frame a správné exact/nearest upozornění. Interakce navíc vyžaduje dokončenou first-interaction fázi, UI Applied výsledek a rule trace. Neprovedená interakce zůstane interrupted. `elapsedMs` zahrnuje otevření stránky a celý runner; není submit-to-frame latencí. Prepared ani nearest dokončení není potvrzení splnění promptu.
