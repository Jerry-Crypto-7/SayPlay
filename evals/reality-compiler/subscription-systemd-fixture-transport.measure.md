# Systemd authored app-server protocol measurement

Explicit opt-in: `RC_SYSTEMD_APPSERVER_FIXTURE_SMOKE=1`. Run `node node_modules/vitest/vitest.mjs run --config vitest.measure.mts evals/reality-compiler/subscription-systemd-fixture-transport.measure.ts` only after transport source review, source freeze and main-agent handoff. Without the opt-in the test is skipped. The harness itself never launches auxiliary subprocesses: its only runtime factory is the fixed `createSystemdAppServerFixtureTransport` capsule.

Predeclared scenarios are normal (30 s), cancellation on confirmed turn start (30 s), and output limit (60 s). The extra setup allowance was selected before any run. The adapter's original 180 s maximum, inner command 200/5 s and manager guardian 220/5 s remain distinct. A failed assertion stops subsequent scenarios; specifically, unknown local or remote cleanup prevents the next factory invocation.

Each scenario must provide pinned CLI/bwrap hashes, exact 2 GiB memory / swap 0 / tasks 64 readback, the same readback immediately before capsule start, an owned UUID unit/leaf identity, and final absence of that unit and leaf with the owned systemd-run process closed. Driver and manager cgroups must be outside the unit leaf. Relay/probe hashes bind receipts to before/after source hashes. The trusted transport enforces pre-start admission; terminal receipts are observations, not cryptographic proof of ordering. No fresh model event or resource credit is invented by this harness.

The current explicit manager identity profile is `private-socket-peer-v1`. The relay obtains SO_PEERCRED from the fixed `/run/user/<uid>/systemd/private` socket, with O_NOFOLLOW traversal of its five components and a retained manager pidfd. The harness requires the exact profile/path, component metadata, manager UID equal to both unit owner and capsule UID, final socket owner UID, decimal manager start ticks and exact equality of the ready and terminal control receipts. Pre-start the relay obtains fresh peer/metadata observations and checks their equality, including manager PID equal to the unit MainPID's parent and unchanged process generation. These are source-enforced admission checks; the harness does not independently connect to the socket, read process metadata or claim executable attestation. In particular, it does not read the non-dumpable manager's `/proc/PID/exe`. This is a separate explicit source profile from the previous public D-Bus name-owner approach, not an automatic runtime fallback.

The bootstrap revision additionally requires decimal `unitMainStartTimeTicks` in both ready and terminal control receipts. Exact full-control equality binds the observed MainPID generation; pre-start comparison remains enforced by the relay. Full manager discovery runs before unit spawn. On failure the harness writes the received `systemdFailure` object separately before checking cleanup. Its bounded `stageEvidence` includes up to 64 stage events, an explicit dropped-event count, optional process snapshot and optional parsed inner terminal with the original raw hash. These diagnostic snapshots are preserved without promoting inner cleanup or ready fields to adapter credit. The parsed inner terminal is not advertised as retained exact raw bytes, and its supplied raw hash is not a hash of reserialized JSON.

Artifacts are new UUID directories under `scratch/session8-systemd-appserver-fixture-ts-*`. Sources are hashed before and after all scenarios. Runtime hashes are the actual ready observations per scenario, not a new independent after-run ELF hash or atomic snapshot. The input list excludes unrelated concurrent work. Planned expectations precede dispatch; failure summaries and earlier evidence remain intact.

Raw stdout/stderr are archived separately from normalized JSON and accounting. Received bytes, aggregate observed bytes, withheld tail and retained UTF-8 body sizes are distinct. There are no invented per-stream observed totals. Output-limit retains at most 8 MiB; terminal `outputComplete` does not imply the harness retained all observed bytes. Late evidence is separate and must be empty at the checked post-cleanup event-loop boundary; this finite observation is not a claim about arbitrary future callbacks.

This is an actual OS pipe/resource/cleanup experiment with authored protocol events and **zero actual model calls**. Adapter `modelCalls:null` remains unknown. Both ready and terminal must explicitly declare `aggregateResourceReadbackValidated:true` and `candidateExhaustionValidated:false`; the legacy aggregate flag alone is insufficient. No authentication, production network, inference, hostile-descendant isolation, candidate-limit exhaustion, browser, GPU or production readiness credit is awarded. Native Windows credential operations and credential reads are outside scope.

Any new runtime result applies only to this reviewed source profile; the four historical systemd failures and older basic measurements receive no retrospective lockdown credit.
